# 示例与用户数据

## 教学合成数据

`a549_teaching_synthetic.csv` 是为测试 e-cell 的“导入—对齐—粗校准—留出验证”流程而制作的**教学合成数据**。它不是湿实验结果、公开数据库下载数据或患者数据。数值以 A549 的默认培养设置为背景，加入固定的、预先写入的数据偏移，目的是让验证脚本可重复运行并能报告非零误差。

该文件可公开分发；它不能用于推断 A549 的真实生长率、摄取率、药物反应或任何临床结论。

一键教学案例脚本会核对该示例文件的 SHA-256 内容指纹；核对前仅对仓库自带示例的 CRLF/LF 换行做规范化，以兼容 Windows 检出。用户上传文件的指纹仍按原始字节计算。若有意修订教学数据，应同时审查训练/留出划分、误差输出和脚本中的预期指纹。指纹只能确认文件内容一致，不能证明数据来自真实实验。

## CSV 格式

首列必须为时间，推荐使用 `time_h`（小时）。可选列及单位：

| 列名 | 含义 | 单位 |
| --- | --- | --- |
| `viable_cells` | 活细胞数 | cells |
| `viability_percent` | 存活率 | % |
| `glucose_mM` | 葡萄糖 | mM |
| `lactate_mM` | 乳酸 | mM |
| `pH` | 酸碱度 | 无量纲 |
| `oxygen_percent` | 培养模型的局部氧可用性代理，不是溶氧饱和度或分压 | 模型刻度 0–21% |

应用会接受常见中文或英文别名，详见 `experiment_data.py`。每个文件应对应一个已明确记录的细胞系、接种量、培养容器、体积、培养基、环境及采样方案；混合批次或未注明单位的数据不应直接用于校准。最低建模条件至少包括两个可用时间点和一种可比较指标；若要报告留出误差，建议预先留出后段或独立批次的多个时间点。时间必须是从实验起点开始的有限非负小时；时间缺失或无法解析的原始行会在报告中阻止对齐/校准，不会因标准化副本删除该行而悄悄通过检查。原始时间倒序会提示核对；标准化副本会按时间排序，但不会覆盖原始文件。负浓度/细胞数、无穷值、超过 100% 的存活率、常规标度之外的 pH、超过 100% 的氧百分比会被阻止。指标缺失会给出警告，重复时间与疑似单位错误也会提示检查。通过格式检查不等于实验设计或生物学结论有效。

若数据没有 0 h 起点，报告会警告初始条件不能仅由该 CSV 核对；这不自动证明数据无效，但进行模型对齐时必须另行确认实验与模拟使用同一时间原点和初始培养条件。

同一指标若有多个可识别列名（如 `glucose_mM` 与“葡萄糖”同时存在），导入会阻止继续并要求确认列与单位。重复时间的标准化副本保留原 CSV 中该时间的最后一行；已识别但全空的列仍会保留并列入缺失值警告。原始文件不会被覆盖。

CSV 各数据行的列数必须与表头一致。不要在数值字段中直接写未加引号的千位逗号（如 `1,000`）；它会被当作额外一列而阻止导入。即使用引号包裹，当前数值标准化也不会自动猜测千位格式，请先在受控副本中转换为 `1000` 并保留原文件。

在线原型当前最多解析 5 MiB、5,000 行的 CSV。此限制仅为共享服务的内存与响应时间保护，不是实验数据充分性或有效性的判断；较大文件请保留原始记录，另制可追溯的时间序列副本用于本工具。

真正未测量的单元格可留空或写 `NA`、`N/A`、`null`。非空但无法解析的数字（例如 `five`）会在质量报告中阻止对齐与校准，不会被静默当成普通缺失值。标准化副本仅供检查，原始 CSV 始终由上传者保存。

`oxygen_percent` 仅与当前模型的 0–21% 局部氧代理同名。实测溶氧饱和度、氧分压、培养箱设定氧和细胞表面氧不是同一个量；`DO`、`dissolved oxygen` 和“溶氧”等泛称不会自动映射到该列。大于 21 的代理输入会阻止比较，量程内输入仍会提示核对测量定义和换算依据。没有经验证的对应关系时，请不要把实测氧列映射到该模型变量。

当前培养模型将状态 pH 限制在 6.2–8.0；该范围外的观测会阻止用于此版本的模型对齐/校准，以免与被裁剪的模拟值比较。这是模型适用范围检查，不代表原始 pH 记录一定错误。

## 隐私与公开边界

请勿向公开仓库提交患者信息、可识别供体信息、未公开实验数据、受限材料转让协议数据、仪器账号信息、访问令牌或含个人信息的实验记录。涉及人源样本或临床资料时，请仅在获批的受控环境中处理，并遵循机构伦理、数据治理和知情同意要求。
